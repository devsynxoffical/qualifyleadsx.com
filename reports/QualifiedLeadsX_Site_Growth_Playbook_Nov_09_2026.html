To hire an appointment setter, first decide what the setter will own: inbound follow-up, outbound outreach, or both. What does an appointment setter actually do?

An appointment setter turns leads into booked, qualified sales calls. In a high-ticket business, that means:

  • Replying to new leads within minutes by phone, SMS, WhatsApp or DM
  • Asking qualifying questions about budget, timeline, decision-maker status and fit
  • Booking qualified leads into the closer's calendar
  • Confirming and reminding, so booked calls actually happen
  • Logging everything in the CRM

A setter is not a closer. Setters protect the closer's time, and closers sell. See outsourced sales closers for the other half of the team.

import type { MetadataRoute } from "next";
import { site } from "@/lib/site";
import { allSitemapEntries } from "@/lib/sitemap-entries";

/**
 * Sitemap split by page type (Site Growth Playbook, STEP 5):
 *   /sitemap.xml            sitemap index
 *   /sitemap-core.xml       home, services, hubs, comparisons, proof, company
 *   /sitemap-industries.xml /for/[industry] and /[service]-for-[industry]
 *   /sitemap-locations.xml  location pages (none yet; listed only when they exist)
 *   /sitemap-content.xml    blog, glossary, free tools and benchmarks
 */
export type SitemapType = "core" | "industries" | "locations" | "content";
export const SITEMAP_TYPES: SitemapType[] = ["core", "industries", "locations", "content"];

export function typeOf(path: string): SitemapType {
  const first = path.split("/")[1] ?? "";
  if (first === "locations") return "locations";
  if (first === "for" || first.includes("-for-")) return "industries";
  if (["blog", "glossary", "tools", "benchmarks"].includes(first)) return "content";
  return "core";
}

const pathOf = (url: string) => url.replace(site.url, "") || "/";

export function entriesFor(type: SitemapType) {
  return allSitemapEntries().filter((e) => typeOf(pathOf(e.url)) === type);
}

const esc = (v: string) =>
  v.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;").replace(/"/g, "&quot;").replace(/'/g, "&apos;");

const day = (d: MetadataRoute.Sitemap[number]["lastModified"]) =>
  d ? new Date(d).toISOString().slice(0, 10) : undefined;

const xmlResponse = (body: string) =>
  new Response(body, { headers: { "Content-Type": "application/xml; charset=utf-8" } });

export function urlsetResponse(type: SitemapType) {
  const urls = entriesFor(type)
    .map((e) => {
      const lm = day(e.lastModified);
      const imgs = (e.images ?? [])
        .map((i) => `<image:image><image:loc>${esc(i)}</image:loc></image:image>`)
        .join("");
      return `<url><loc>${esc(e.url)}</loc>${lm ? `<lastmod>${lm}</lastmod>` : ""}${imgs}</url>`;
    })
    .join("\n");
  return xmlResponse(
    `<?xml version="1.0" encoding="UTF-8"?>\n<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9" xmlns:image="http://www.google.com/schemas/sitemap-image/1.1">\n${urls}\n</urlset>\n`,
  );
}

export function indexResponse() {
  const items = SITEMAP_TYPES.map((type) => ({ type, entries: entriesFor(type) }))
    .filter((s) => s.entries.length > 0)
    .map(({ type, entries }) => {
      const newest = entries.map((e) => day(e.lastModified)).filter(Boolean).sort().pop();
      return `<sitemap><loc>${site.url}/sitemap-${type}.xml</loc>${newest ? `<lastmod>${newest}</lastmod>` : ""}</sitemap>`;
    })
    .join("\n");
  return xmlResponse(
    `<?xml version="1.0" encoding="UTF-8"?>\n<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">\n${items}\n</sitemapindex>\n`,
  );
}

Daily routine while pages are going live

  1. Publish the day's pages: merge to main, and Hostinger deploys.
  2. Open each page with JavaScript off (curl -s URL | grep "<h1", or view source) and check that the full text is in the HTML.
  3. Request indexing in Search Console. The manual tool has a daily limit, so do hubs and core pages first. Or run npm run index:google -- <urls>; the Indexing API quota is 200 a day and is shared with the other project.
  4. Ping IndexNow: npm run index:now (add the new URLs to scripts/submit-indexnow.mjs).
  5. Add the new pages to lib/related-links.ts and to their hub page the same day. Location pages also need a "Where we work" group added to the service rules.
  6. Log the URLs in the tracker, then run npm run build && python3 -I scripts/playbook-audit.py && npm run seo:links. The page must show "keep", with 5+ internal links in.

7. Weekly measurement checklist (STEP 7)

Weekly measurement checklist (every Monday)

In Search Console, Performance, last 7 days compared with the previous 7:

  • [ ] Filter pages containing /locations/: record impressions, clicks and average position
  • [ ] Filter pages containing -for-, and separately /for/: same three numbers (industry pages)
  • [ ] Filter pages containing /tools/, and separately /benchmarks/: same three numbers
  • [ ] Filter pages containing /blog/: same three numbers
  • [ ] Everything else (core): same three numbers
  • [ ] Work out impressions per page for each type (impressions ÷ number of live pages of that type)

In Search Console, Indexing, Pages, filtered by sitemap:

  • [ ] For sitemap-core.xml, sitemap-industries.xml, sitemap-locations.xml and sitemap-content.xml, record indexed vs not indexed
  • [ ] If more than 20% of a group is "Crawled, currently not indexed", stop publishing that type. Add unique content to the existing pages first, because they are too similar.

Decide:

  • [ ] Expansion rule: the page type with the most impressions per page gets the next batch. If locations win, add cities where fact 5 confirms clients. If industries win, add more service-for-industry pages.
  • [ ] Queries in positions 8 to 20: in Performance, Queries, filter position > 7.9 and < 20.1. Add each relevant query as an H2 or FAQ question on the page that ranks for it, then request reindexing.
  • [ ] Cannibalisation: if two URLs get impressions for the same query, pick one primary page and point the other to it with an internal link, or merge the two.
  • [ ] Re-run python3 -I scripts/playbook-audit.py: "merge or differentiate", "shorten title", "shorten description" and "add links" must all be 0.
